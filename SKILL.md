# RTL → Formal IP Specification (Synopsys VCS + Verdi)

**Invocation:** `<skill>` means this Skill's directory, the directory containing `SKILL.md`. Work at the selected RTL project's root; outputs go only into `docs/rtl_spec` by default. Users may request another output folder. Never modify DUT `.v`, `.sv`, `.vh`, `.svh`, third-party source, proprietary testbenches, or build configurations without the user's explicit authorization.

**Goal:** Produce **as-implemented**, review-ready IP specifications following the fixed numbered chapter layout in [formal spec contract](references/spec-contract.md). Document evidence from real RTL, **not** intent, typical interface conventions or speculation. Keep the content in the user's preferred language; preserve the numbered English chapter keys (optional Chinese subtitle) and RTL identifiers for validation. Generated output is DRAFT until actual review/approval.

## 中文写作原则（默认执行）

阅读 [工程中文写作规范](references/writing-style-zh.md)。Spec 要像资深 RTL 工程师讲设计：**先说功能，再说触发条件、寄存器/输出变化和周期关系**。采用清晰、直接的中文，避免翻译腔、堆砌术语和套话。保留信号名、公式、精确的周期、源代码引用及所有正式章节。

**防御性说明集中管理**：正文不反复写「仅依据 RTL」「没有证明正确」「不保证」之类句子；在第 12 章（模块第 8 章）如实记录 VCS/Verdi 执行情况，第 13 章记录具体待确认事项。图题简写「RTL 推导」或「VCS/Verdi 波形」，详细文件哈希与工具状态写验证矩阵和 `.meta.json`。不伪造验证或隐藏影响集成的工程条件。

## Workflow (required order)

1. **Read hierarchy and build configuration.** Inspect the project's current VCS filelist and source tree: actual DUT top, tb top, nested `-f` files, package order, `+incdir+`, compile defines, parameters, generated sources, libraries, encrypted IP and black boxes. Run `python3 <skill>/scripts/doctor.py` and `python3 <skill>/scripts/inventory.py --root . --filelist RTL_FILELIST --out docs/rtl_spec/inventory.json` (omit `--filelist` only when absent). Inventory is **lexical only**, never full SV elaboration. Resolve ambiguous top module explicitly. Use real VCS compile/elaboration logs to substantiate `TOOL-ELABORATED` claims if the tool is available.
2. **Create controlled, non-overwriting drafts.** `python3 <skill>/scripts/scaffold.py --root . --inventory docs/rtl_spec/inventory.json --out docs/rtl_spec --top DUT_TOP`. Fill `ip_spec.md`, `modules/*.md` with actual analysis; the scaffold contains TODO placeholders and is not an output-ready Spec. Do not overwrite user-edited documents without permission. Require IP chapters **1–13 and Appendices A/B**, module chapters **1–9**, title/document metadata, revision history, numbered figure/table captions, interface and state tables, verification evidence matrix, source traceability and N/A rationales.
3. **Analyze actual RTL in depth.** For all relevant modules and the real compile configuration: parameters, exact port widths/types, clocks/resets and release, CDC, internal registers, state/datapath equations, FSM transitions, handshake boundaries, stall/flush, error/interrupt behavior and cycle-exact latency/throughput. Differentiate pre-edge accepted handshakes from post-NBA outputs. Write function-first Chinese explanations, then equations/tables. Cite verifiable `path/to/source.sv:NN` or ranges for concrete claims; resolve configuration-dependent branches or mark UNKNOWN. Do not invent memory mapped registers when none exist; use evidence-based N/A.
4. **Generate formal diagrams and scenario coverage.** Include source-backed architecture Mermaid with **Figure 5-n** caption, interface/clock/register tables with **Table X-n** captions, separate timing scenarios for supported reset, single operation, consecutive transactions, stalls and exceptional behavior. Every important timing scenario has ID/objective, start conditions, sampled signal set, cycle table, source lines, **Figure 9-n** (IP) or **Figure 7-n** (module), and a linked `.json5` + `.svg`. Produce illustrative data in `waveforms/<name>_illustrative.json5`, render using `python3 <skill>/scripts/render_wavedrom.py --input ...json5 --output ...svg`; label the figure **RTL 推导**; keep unsimulated provenance in metadata/verification records. Never present an inferred wave as a real trace.
5. **Use the required vendor EDA flow when locally available and authorized.** **Synopsys VCS** is the primary simulator/elaborator; **Synopsys Verdi** is the primary FSDB debug system. Follow [VCS + Verdi guide](references/eda-vcs-verdi.md), not Icarus/Verilator as the default. Use existing licensed installations and approved TB. Customize a copy of `assets/templates/vcs_verdi_config.json`; plan with `python3 <skill>/scripts/vcs_verdi.py --config vcs_verdi.json plan` (offline, no execution), then **only when authorized, licensed and installed** run `--execute compile`, `--execute run`, `--execute convert` separately. Compile with appropriate `-kdb`/`-debug_access`, capture FSDB using existing TB dump tasks or optional VCS UCLI dump recipe, inspect FSDB in Verdi, use Verdi `fsdb2vcd` for selected time/scopes. This Skill's Python scripts are adapters, not replacement EDA. If unavailable, record **VCS/VERDI NOT RUN** with reason; still complete source-backed DRAFT docs and illustrations.
6. **Link observed waves only with authentic command/file chain.** After real VCS FSDB run and Verdi conversion, call `python3 <skill>/scripts/vcd_to_wavedrom.py --vcd docs/rtl_spec/eda/waves.vcd --clock tb_top.clk --signals ... --verdi-manifest docs/rtl_spec/eda/convert_manifest.json --vcs-run-manifest docs/rtl_spec/eda/run_manifest.json --out docs/rtl_spec/waveforms/example_observed.json5 --svg docs/rtl_spec/waveforms/example_observed.svg`. Converter checks VCD+FSDB hashes and stage status before using label **VCS/Verdi 波形**. Without BOTH run/conversion manifests, it labels raw VCD as an unauthenticated observation. If showing actual Verdi GUI inspection, record inspected window/signal list/reviewer; GUI launch alone is not verification. Use `compare_waveforms.py` only for explicitly edge-aligned examples, never as a proof of RTL behavior.
7. **Publish only after structural and provenance QA.** Read each section for clarity, then run `python3 <skill>/scripts/style_lint.py --docs docs/rtl_spec --strict` and `python3 <skill>/scripts/validate.py --root . --docs docs/rtl_spec --inventory docs/rtl_spec/inventory.json --strict`. Fix missing/unnumbered sections, draft placeholders, missing SVG, misleading origin labels, wrong source lines and changed RTL hashes. Keep document status DRAFT/UNDER REVIEW until an authorized reviewer approves a release. Record actual verification outcomes only once, in the appropriate section. `--release` is an *additional* evidence gate, not an automated sign-off. Report precisely which checks ran, failed, skipped and what remains unverified. Follow [timing protocol](references/timing-and-validation.md).

## Tool priorities and constraints

- **Required vendor combination:** VCS (`vcs`/`simv`) + Verdi (`verdi`, `fsdb2vcd`) for **EDA-supported claims**. Never substitute Icarus, Verilator, Yosys, wave-mcp or waveform sketches as confirmation that the requested vendor flow passed. No vendor executables/licenses are bundled.
- **Offline authoring always supported:** lexical inventory, Markdown templates, reviewable RTL-derived documentation, strict-JSON WaveDrom subset to SVG, VCD inspection of external files, structure validation. If no VCS license/tool/testbench exists, no simulation is claimed.
- **Evidence classes:** `RTL-DERIVED` source reasoning, `TOOL-ELABORATED` recorded VCS, `ILLUSTRATIVE` unsimulated chart, `VCS/VERDI OBSERVED` sampled FSDB trace, `SIMULATION-PASS` only with a checked self-checking TB. In readable prose, prefer short Chinese labels and put detailed evidence in the verification tables.
- **Data stewardship:** Keep confidential DUT, FSDB, proprietary source and testbench output local; do not push these to GitHub or external providers. Write only requested docs and build products under the designated output path. Do not perform unapproved installations, uploads, new remote execution, or destructive overwrites.

## Output contract

`docs/rtl_spec/ip_spec.md` + `modules/*.md` + `inventory.json` + `waveforms/*.json5` + `waveforms/*.svg` + `validation_report.json`; optional `style_report.json`, `eda/{compile,run,convert}_manifest.json`, `eda/*.fsdb`, `eda/*.vcd`, `waveforms/*.meta.json` and `waveform_compare_report.json`. Vendor artifacts should be excluded from Git. Maintain source-line references in prose and an Open Issues register. Default output language follows user request; sections remain English-numbered.
